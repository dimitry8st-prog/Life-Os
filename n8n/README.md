# Еженедельный MIT-поток Life-OS

`lifeos-mit-rss-to-notion.json` продолжает исходный workflow, интервал 168 часов.
Новая цепочка: MIT RSS → фильтр → хранение на st8dom.ru → очередь отчётов →
поиск отчёта в Notion → создание при отсутствии → подтверждение на портале.

## Перед запуском

1. На сервере st8dom установить `LIFEOS_INGEST_TOKEN` в окружении приложения.
   Пустой ключ отключает API. Секреты не добавлять в JSON или Git.
2. В n8n импортировать файл через Import from URL:
   `https://raw.githubusercontent.com/dimitry8st-prog/Life-Os/main/n8n/lifeos-mit-rss-to-notion.json`.
   Если этот workflow уже импортирован, обновить его; не активировать две копии.
3. В Save on Portal, Load Pending Reports, Confirm New Report и Confirm Existing
   Report выбрать один Header Auth credential: заголовок Authorization,
   значение `Bearer <LIFEOS_INGEST_TOKEN>`.
4. В Find Notion Report и Create Notion Item выбрать Notion API credential,
   которому открыт доступ к базе «Life-OS — отчёты источников».
5. Выполнить Manual Test, проверить портал и Notion, повторить без дублей.
6. Активировать только после проверки. Интервал 168 часов отсчитывается от запуска
   расписания и не означает фиксированную пятницу; календарную пятницу настроить
   отдельно при необходимости. Часовой пояс Europe/Moscow.

## Хранение и восстановление

Сохраняются заголовок, анонс, ссылка и дата. Анонс не считается проверенным
исследованием. Три научных потока: AI, медицина/нейронауки, долголетие.
В Notion отправляются только заголовок, короткий отчёт и ссылка на материал портала.
Полные тексты, DOI, авторская оценка и публикация статей — отдельные этапы.

URL уникален в БД портала. Очередь pending хранит материалы до успешного ack,
независимо от их наличия в текущем RSS. Если RSS временно недоступен, для передачи
ранее сохранённой очереди временно соединить Manual Test непосредственно с Load
Pending Reports, выполнить тест и вернуть соединение с MIT RSS.
За один запуск обрабатывается до 100 pending-записей; при накоплении очереди
повторить ручной запуск после завершения предыдущего.

После таймаута Notion Create не повторяется автоматически: следующий запуск
сначала ищет отчёт по portal_url, затем подтверждает найденный UUID. При двух
совпадениях требуется ручное решение. Query/create не атомарны: не запускать
два выполнения одновременно. После удаления/архивации подтверждённого отчёта
автоматического пересоздания нет. HTTP ошибки останавливают выполнение; детали
сохраняются в n8n executions. Сохранение на портале остаётся выполненным.
