# CLAUDE.md — правила проекта Life OS

> Этот файл читается ПЕРВЫМ в начале каждого сеанса работы над проектом.

## Название проекта

**Life OS** — персональная система управления знаниями (автоматический конвейер сбора знаний в Obsidian).

## Области знаний

1. Промпт-инжиниринг (`prompt-engineering`)
2. Вайб-кодинг (`vibe-coding`)
3. Долголетие (`longevity`)
4. Бессмертие / радикальное продление жизни (`immortality`)
5. Прочее (`other`) — при низкой уверенности классификации

## Стек (НЕ менять без явного согласия владельца)

- Obsidian (Markdown-хранилище)
- Python 3.12
- SQLite
- Локальный RAG (эмбеддинги + чанкинг)
- Claude API (Anthropic)
- Git

## Целевая ОС: Windows

- Все пути — только через `pathlib.Path`, никаких жёстко прописанных `/` или `\`.
- Чтение/запись файлов — всегда с явным `encoding="utf-8"`.
- Инструкции запуска — кроссплатформенные (`python capture.py ...`), никаких bash-only команд.

## Структура хранилища Obsidian

```text
/Inbox                      — необработанные материалы
/Notes                      — постоянные заметки
/Areas
    /Prompt-Engineering
    /Vibe-Coding
    /Longevity
    /Immortality
/Projects
/Tags
```

Путь к хранилищу задаётся ТОЛЬКО в `config.yaml` (ключ `vault_path`).
Если путь не задан — спросить у владельца один раз и записать в конфиг. Не хардкодить.

## Конвейер (цель)

Вход (URL / PDF / текст) → извлечение контента → Claude API (классификация, саммари,
ключевые идеи, научный блок) → `.md`-заметка в vault + запись в SQLite + чанки в RAG-индекс.

## Формат заметки — строгий

Frontmatter: `title, date, source, area, type, tags, related, status`.
Разделы: `## Саммари`, `## Ключевые идеи`, `## Для научных материалов` (только при
`type: paper`), `## Мои мысли` (ВСЕГДА пустой — только ручное заполнение),
`## Исходник`.

## Жёсткие правила

1. **Никогда не перезаписывать существующие заметки** в хранилище — только создавать новые.
   Любая операция с риском перезаписи требует явного подтверждения владельца.
2. Работа строго по фазам (0 → 1 → 2 → 3 → 4). Следующая фаза не начинается,
   пока текущая не принята владельцем. Не переносить функциональность из будущих фаз.
3. Одна фаза = один пул-реквест / один осмысленный коммит.
4. Ошибки конвейера не прерывают процесс: логировать в файл (`logs/`) и в SQLite
   (`status = failed` + причина).
5. API-ключи — только из переменных окружения / `.env`. Файл `.env` в `.gitignore`.
6. Теги — только из уже существующих в хранилище; новые теги предлагать владельцу,
   а не создавать автоматически.
7. Тесты обязательны минимум на: классификацию области и парсинг frontmatter.
8. Если требование неясно — задать вопрос, не додумывать.

## Команды запуска

```text
pip install -r requirements.txt        # установка зависимостей
python init_db.py                      # создать/проверить БД
python capture.py <url|путь_к_файлу>   # захват материала (фаза 1+)
python -m pytest tests/                # тесты
```
